Roles & approvers
Developer
approves: own feature PRs
Writes code, raises PRs, resolves conflicts in own branch. References JIRA ticket in every commit message.
Tech Lead
approves: release → dev, PR to master
Reviews code quality, reviews revert list before step 4, provides second approval for conflict resolution PRs.
QA Engineer
approves: qa branch promotion
Validates builds on QA environment. Records sign-off in PR comment with JIRA ticket IDs before any qa merge.
Release Manager
approves: final PR to master
Owns release schedule, identifies commits to remove on release_qa, dry-runs conflict check, approves go-live.
DevOps Engineer
approves: pipeline config only
Configures CI/CD pipelines, enforces branch protection rules in GitHub, manages deployment infrastructure.
Compliance & audit policies
Change freeze
  • Last 2 business days of each sprint
  • Public holidays & weekends
  • Active P1/P2 production incidents
  • Scheduled maintenance windows
  • Requires Release Manager override to bypass
Hotfix process
  • Branch directly from master
  • Name: hotfix/<ticket-id>
  • Minimal scope — fix only
  • Requires Tech Lead + Release Manager (2 approvals)
  • Back-port to dev and qa immediately after merge
Audit & traceability
  • Retain PR history with reviewer names & timestamps (12 months)
  • Commit log for release_qa with author + timestamp
  • CI/CD pipeline run logs per deployment
  • QA sign-off records linked to JIRA tickets
  • Conflict resolution branch history
Git rules
RuleReason
Always use git revert — never git reset on shared branchesRevert preserves history; reset rewrites it and breaks other developers' copies
Commit selection filter: developer + Monday–Wednesday window + approved onlyPrevents unrelated or untested changes reaching Production
Always dry-run merge (--no-commit --no-ff) before raising PR to masterDetects conflicts before they block the release pipeline
Resolve conflicts in isolated release_master branch — never on master directlyProtects Production branch from unstable state during conflict resolution
Tag every production release (git tag -a v{major}.{minor}.{patch})Enables precise rollback and audit trail per release version
Delete release_master after mergeKeeps repository clean; this branch is temporary by design
